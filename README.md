# humanizer-korean

## 무엇인가

`humanizer-korean`은 Claude Code용 스킬이다. 사용자가 이미 가지고 있는 한국어
초안이나 메모 기반 초안을 마지막 단계에서 편집한다. 빈 수사, 정형적인 예고,
중복된 결론, 근거 없는 추상 명사 나열을 줄이되 원문의 사실과 목소리는 그대로
둔다. 새 자료로 초안을 만들거나 음성·영상·업로드 처리는 하지 않는다. 현재
버전은 v0.1.3이다.

## 출처

[blader/humanizer](https://github.com/blader/humanizer)(MIT 라이선스)에서
파생된 작업이다. 원본은 영어 산문을 대상으로 한 편집 규칙을 담고 있고, 이
한국어판은 그 규칙을 그대로 옮긴 번역이 아니라 어미, 조사, 존댓말 격식 같은
한국어 문법 요소에 맞춰 다시 작성한 것이다. 원본 저장소와 라이선스 전문은
`LICENSE` 파일에 남겨 두었다.

## 설치

`~/.claude/skills` 디렉터리가 없다면 먼저 만든다.

```sh
mkdir -p ~/.claude/skills
```

이 저장소를 그 안에 clone한다.

```sh
git clone https://github.com/dante01yoon/humanizer-korean.git ~/.claude/skills/humanizer-korean
```

Claude Code를 재시작하면 스킬 목록에 `humanizer-korean`이 나타난다.

## 사용법

Claude Code에서는 `/humanizer-korean`, Codex에서는 `$humanizer-korean`으로 부른다.
아래 예시는 Claude Code 기준이다.

스킬은 세 가지 모드로 동작한다. 모드는 별도로 지정하지 않아도 요청 문장에 담긴
한국어 표현으로 판단된다.

기본값인 `conservative` 모드는 문단 순서와 정보가 있는 문장 구조를 유지하면서
불필요한 수사만 정리한다.

```
/humanizer-korean 아래 초안을 다듬어줘. 숫자, 고유명사, 조건은 그대로 둬줘.
```

`rewrite` 모드는 `문단/구성을 다시 짜줘`, `읽기 좋게 다시 써줘`, `전면
재작성해줘` 같은 요청에 적용된다. 이때만 문장 병합·분할과 문단 재배열을
허용한다.

```
/humanizer-korean 이 초안 문단 구성을 다시 짜줘. 사실 관계는 바꾸지 마.
```

`spoken` 모드는 `유튜브 대본`, `강의 내레이션`, `말로 읽는 대본`, `구어체
대본` 같은 요청에 적용된다. 편집 강도는 기본값인 conservative를 유지하고,
호흡 분할을 따로 요청하지 않는 한 문장 경계를 임의로 바꾸지 않는다.

```
/humanizer-korean 이 유튜브 대본을 다듬어줘. 문장 경계는 그대로 둬.
```

## 예시 (AS IS / TO BE)

합성 사례 하나를 같은 모델(Claude Sonnet)에 맡긴 실제 출력이다. 손대지 않고 그대로
옮겼고, 여러 번 돌린 것 중 고르지 않고 1회차 출력을 썼다.

**AS IS (원문)**

```text
오늘은 파일 이름을 `2026-09-16_주제` 형식으로 바꾸고, 끝난 파일을 `archive` 폴더에 한 번 복사하는 두 단계를 소개했습니다. 결국 이 작은 정리 습관은 단순한 파일 관리 차원을 넘어, 우리가 일하는 방식 전반을 새롭게 정의하는 출발점이 될 것입니다. 지금 이 순간부터 여러분의 모든 작업은 더 높은 차원의 질서와 몰입으로 연결될 수 있습니다. 두 단계만 기억하셔도 변화의 문은 이미 열렸습니다. 이 여정의 다음 장은 바로 여러분의 실행으로 완성됩니다.
```

**v0.1.1의 결과 (결론까지 지워졌다)**

```text
오늘은 파일 이름을 `2026-09-16_주제` 형식으로 바꾸고, 끝난 파일을 `archive` 폴더에 한 번 복사하는 두 단계를 소개했습니다.
```

**TO BE (v0.1.3)**

```text
오늘은 파일 이름을 `2026-09-16_주제` 형식으로 바꾸고, 끝난 파일을 `archive` 폴더에 한 번 복사하는 두 단계를 소개했습니다. 이 정리 습관은 우리가 일하는 방식 전반의 변화로 이어질 수 있습니다.
```

## 보존하는 것

- 인물·기관·제품명
- 숫자·단위·범위, 소수점과 끝자리 0 (예: `123.1`, `0.5초`, `1,234원`)
- 날짜·시간·사건 순서
- 부정, 가능·추정·의무·확정의 강도 (`-것 같다`, `-로 알려졌다`, `-해야 한다`,
  `-일 수 있다` 등을 더 단정적으로 바꾸지 않는다)
- 조건, 원인과 결과
- 귀속·인용, 행위자와 책임
- 코드 펜스, inline code, 셸 명령, 경로, 식별자, YAML frontmatter, URL과 링크
  대상
- 해요체/합니다체 혼용처럼 작성자가 의도한 어체

## 한계

- v0.1.1 검증은 합성 개발 사례 12개를 두 번씩 실행한 로컬 파일럿이다 (스킬 적용/미적용
  총 48개 raw 출력, 24개 A/B 쌍 모델 리뷰).
- v0.1.1은 과장된 마무리를 걷어내다가 하나뿐인 결론까지 지우는 일이 있었다. 같은
  사례를 6번 실행해 6번 모두 그랬다. v0.1.3에서 삭제와 축약의 기준을 나눠 고쳤고,
  같은 사례 4번 중 4번 결론이 원문의 단어로 남았다.
- v0.1.3 평가는 입력 9개(기존 5개, 새로 쓴 held-out 4개)를 4번씩 실행한 것이다.
  지워야 할 결말에 없던 평가어를 만들어 넣은 경우는 12번 중 0번이었다. 은유로만
  암시된 행동 촉구는 4번 중 1번만 남았다. 명시적인 요청 문장은 4번 모두 남았다.
- 표본이 작고 모델 출력은 실행마다 달라진다. 결과는 원문과 대조해서 쓴다.
- 사람 검토와 실제 낭독·청취 검증은 진행하지 않았다 (`NOT_RUN`).
- 이 스킬은 AI 탐지 도구를 우회하기 위한 것이 아니다. 목적은 틀에 박힌 표현을
  줄이는 편집이며, 특정 AI 탐지기 통과를 보장하지 않는다.
