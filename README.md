# humanizer-korean

## 무엇인가

`humanizer-korean`은 Claude Code용 스킬이다. 사용자가 이미 가지고 있는 한국어
초안이나 메모 기반 초안을 마지막 단계에서 편집한다. 빈 수사, 정형적인 예고,
중복된 결론, 근거 없는 추상 명사 나열을 줄이되 원문의 사실과 목소리는 그대로
둔다. 새 자료로 초안을 만들거나 음성·영상·업로드 처리는 하지 않는다. 현재
버전은 v0.1.1이다.

## 출처

[blader/humanizer](https://github.com/blader/humanizer)(MIT 라이선스)에서
파생된 작업이다. 원본은 영어 산문을 대상으로 한 편집 규칙을 담고 있고, 이
한국어판은 그 규칙을 그대로 옮긴 번역이 아니라 어미, 조사, 존댓말 격식 같은
한국어 문법 요소에 맞춰 다시 작성한 것이다. 원본 저장소와 라이선스 전문은
`LICENSE` 파일에 남겨 두었다.

## 설치

`~/.claude/skills` 디렉터리가 없다면 먼저 만든다.

```sh
mkdir -p ~/.claude/skills
```

이 저장소를 그 안에 clone한다.

```sh
git clone https://github.com/dante01yoon/humanizer-korean.git ~/.claude/skills/humanizer-korean
```

Claude Code를 재시작하면 스킬 목록에 `humanizer-korean`이 나타난다.

## 사용법

스킬은 세 가지 모드로 동작한다. 모드는 별도로 지정하지 않아도 요청 문장에 담긴
한국어 표현으로 판단된다.

기본값인 `conservative` 모드는 문단 순서와 정보가 있는 문장 구조를 유지하면서
불필요한 수사만 정리한다.

```
$humanizer-korean 아래 초안을 다듬어줘. 숫자, 고유명사, 조건은 그대로 둬줘.
```

`rewrite` 모드는 `문단/구성을 다시 짜줘`, `읽기 좋게 다시 써줘`, `전면
재작성해줘` 같은 요청에 적용된다. 이때만 문장 병합·분할과 문단 재배열을
허용한다.

```
$humanizer-korean 이 초안 문단 구성을 다시 짜줘. 사실 관계는 바꾸지 마.
```

`spoken` 모드는 `유튜브 대본`, `강의 내레이션`, `말로 읽는 대본`, `구어체
대본` 같은 요청에 적용된다. 편집 강도는 기본값인 conservative를 유지하고,
호흡 분할을 따로 요청하지 않는 한 문장 경계를 임의로 바꾸지 않는다.

```
$humanizer-korean 이 유튜브 대본을 다듬어줘. 문장 경계는 그대로 둬.
```

## 예시 (AS IS / TO BE)

아래는 합성 개발 사례 하나에 대해 실제 모델이 낸 raw 출력을 손대지 않고 그대로
옮긴 것이다. `humanizer-korean-demo` 저장소의 `reports/showcase.md`에서
가져왔다.

**AS IS (스킬 미적용)**

```text
저는 오늘 `notes.csv`에서 중복 행을 제거하는 과정을 짧게 살펴보겠습니다. 먼저 파일을 열어 중복 값을 확인하고, 삭제할 대상을 확정한 다음 저장하면 됩니다. 원본 파일은 꼭 보존해 주세요. 이렇게 순서대로 진행하면 데이터를 안전하게 정리할 수 있습니다.
```

**TO BE (스킬 적용)**

```text
오늘은 `notes.csv`에서 중복 행을 제거하는 방법을 살펴볼게요. 먼저 파일을 열고 중복 값을 확인합니다. 그다음 삭제할 대상을 확정한 뒤 저장하면 됩니다. 원본 파일은 꼭 보존해 주세요.
```

## 보존하는 것

- 인물·기관·제품명
- 숫자·단위·범위, 소수점과 끝자리 0 (예: `123.1`, `0.5초`, `1,234원`)
- 날짜·시간·사건 순서
- 부정, 가능·추정·의무·확정의 강도 (`-것 같다`, `-로 알려졌다`, `-해야 한다`,
  `-일 수 있다` 등을 더 단정적으로 바꾸지 않는다)
- 조건, 원인과 결과
- 귀속·인용, 행위자와 책임
- 코드 펜스, inline code, 셸 명령, 경로, 식별자, YAML frontmatter, URL과 링크
  대상
- 해요체/합니다체 혼용처럼 작성자가 의도한 어체

## 한계

- 검증은 합성 개발 사례 12개를 두 번씩 실행한 로컬 파일럿이다 (스킬 적용/미적용
  총 48개 raw 출력).
- 완료된 검증은 24개 A/B 쌍에 대한 모델 리뷰뿐이다. 사람 검토와 실제 낭독·청취
  검증은 진행하지 않았다 (`NOT_RUN`).
- 이 검증은 held-out 성능 평가가 아니며, 더 큰 규모의 release benchmark를
  대체하지 않는다.
- 이 스킬은 AI 탐지 도구를 우회하기 위한 것이 아니다. 목적은 formulaic한 표현을
  줄이는 편집이며, 특정 AI 탐지기 통과를 보장하지 않는다.
